## 1. 화면의 원칙

1. **읽기가 먼저다.** 키, 네트워크, 튜터 상태와 관계없이 PDF는 언제나 읽을 수 있다. 어떤 안내도 뷰어를 막지 않는다. 앱 전체를 막는 대화상자는 되돌릴 수 없는 삭제 확인에만 쓴다.
2. **보이는 범위가 곧 보내는 범위다.** 화면의 범위 표시와 실제 요청은 같은 데이터에서 나온다(3.3절).
3. **요청하지 않으면 AI를 호출하지 않는다.** 쪽을 넘기거나 텍스트를 선택해도 호출과 제안이 일어나지 않는다. 호출은 사용자가 누른 동작으로만 시작한다.
4. **입력한 내용을 잃지 않는다.** 키 설정, 오류, 패널 접기, 문서 전환 어디서도 질문이 사라지지 않는다.
5. **MVP에 없는 기능은 흔적도 두지 않는다.** 비활성 버튼, '곧 제공' 표시, 빈 탭을 만들지 않는다(13절 점검표).

## 2. 레이아웃

### 2.1 구조

창 하나에 문서 하나를 연다. 왼쪽이 뷰어, 오른쪽이 튜터 패널이다.

```text
+---------------------------------------------------------------------+
| ● ● ●  파일명.pdf   [<] 12 / 80 [>]  [-] 110% [+] [폭 맞춤]  [영역 선택] [패널] |  도구 막대 44px
+----------------------------------------------+----------------------+
| (진단 배너: 필요할 때만)                       | 튜터            [...] |  패널 머리 40px
|                                              |----------------------|
|   p.12                                       | 대화 영역(스크롤)     |
|   +------------+                             |  내 질문              |
|   | 수식 (4)   | ← 선택 영역                  |  보낸 범위: p.11~13   |
|   +------------+                             |  읽은 내용 [잘못 읽음] |
|                                              |  답변 ... 근거 p.12   |
|   p.13                                       |  [p.12 이해도 확인]   |
|                                              |----------------------|
|                                              | 보낼 범위 p.11~13     |
|                                              | 선택 영역 1개(p.12)   |
|                                              | 이전 대화 일부 · OpenAI|
|                                              | [썸네일] 선택 영역 [x] |
|                                              | 질문 입력             |
|                                              | [이해도 확인]  [보내기]|
+----------------------------------------------+----------------------+
```

PRD 11절 그림은 범위 표시를 패널 위쪽에 두었으나, 이 계약은 입력창 바로 위로 옮긴다. 이유는 12절 판단 2에 있다.

### 2.2 창 크기

| 항목 | 값 | 비고 |
|---|---|---|
| 기본 창 | 1200 × 800 | 앱 골격 값과 같다. 화면보다 크면 작업 영역에 맞춘다 |
| 최소 창 | 800 × 600 | 뷰어 최소 440 + 패널 최소 360. 앱 골격 값과 같다 |
| 창 크기·위치 복원 | 재실행 시 복원 | [제안] 화면 밖이면 기본값으로 되돌린다 |
| 전체 화면 | 지원 | macOS 기본 동작 |

분기점은 두지 않는다. 800px 이상 어디서나 뷰어와 패널을 나란히 놓는다. 패널이 뷰어를 덮는 모드는 만들지 않는다. 선택한 수식을 보면서 답을 읽는 것이 제품의 핵심이기 때문이다.

### 2.3 패널 크기와 접기

| 동작 | 규칙 |
|---|---|
| 기본 폭 | 창 폭의 33%, 360~440px 범위로 제한 |
| 조절 범위 | 최소 360px, 최대 `min(560px, 창 폭 - 440px)` |
| 조절 방법 | 뷰어와 패널 사이 구분선 끌기. 보이는 선은 1px, 잡는 영역은 8px |
| 초기화 | 구분선 더블클릭으로 기본 폭 |
| 키보드 | 구분선에 포커스 후 ←/→로 16px씩. `role="separator"`와 현재 폭 값을 제공 |
| 저장 | 사용자가 조절한 폭과 접힘 상태를 앱 전체 설정으로 저장 [제안] |
| 창을 줄일 때 | 뷰어가 최소 폭이 될 때까지 먼저 줄고, 그 뒤 패널이 줄어든다 |
| 창을 늘릴 때 | 저장된 패널 폭까지 먼저 회복하고, 나머지는 뷰어가 차지한다 |
| 끄는 중 렌더링 | 쪽은 CSS 배율로 임시 조정하고 끌기가 끝나면 다시 그린다. 현재 쪽 위치를 유지한다 |

**접기**

- 도구 막대 오른쪽 끝의 [패널] 버튼과 `⌃⌘S`로 접고 편다. 접으면 폭은 0이고 뷰어가 전체를 쓴다. 가장자리 띠를 남기지 않는다.
- 접어도 입력 중인 질문, 선택, 진행 중인 답변을 유지한다. 답변이 진행 중이거나 접힌 사이에 끝나면 [패널] 버튼에 상태 점과 접근성 이름("답변 받는 중", "새 답변 있음")을 표시한다.
- 접힌 상태에서 영역 선택을 마치거나 `⌘L`을 누르면 패널이 펴진다. 텍스트 선택만으로는 펴지 않는다(5.5절).
- 접혀 있는 동안은 입력창이 없어 전송할 수 없으므로 범위 표시도 필요하지 않다.

### 2.4 패널 세로 배치

위에서 아래로 패널 머리, 대화 영역, 입력 블록 순이다. 대화 영역만 스크롤한다. 입력 블록은 항상 패널 바닥에 붙어 있고 가려지지 않는다.

| 요소 | 높이 |
|---|---|
| 패널 머리 | 40px 고정 |
| 입력 블록의 범위 표시 | 내용만큼. 기본 2줄, 경고가 있으면 3줄 |
| 입력 블록의 선택 칩 | 선택이 있을 때만 52px |
| 입력창 | 최소 64px, 최대 160px. 넘으면 입력창 안에서 스크롤 |
| 대화 영역 | 나머지 전부 |

최소 창(600px)에서 모든 요소가 최대일 때도 대화 영역에 약 180px이 남는다. 이보다 작아질 조건은 없다.

### 2.5 뷰어

- **보기 방식:** 세로 연속 스크롤, 한 줄에 한 쪽. 두 쪽 펼침과 썸네일·목차 사이드바는 MVP에 없다(F1 범위 밖).
- **도구 막대:** 파일명, 이전·다음 쪽, 쪽 번호 입력(`12 / 80`), 축소·배율·확대, 폭 맞춤, 영역 선택, 패널 접기. 왼쪽은 창 제어 버튼 자리 78px를 비우고, 막대의 빈 곳으로 창을 끌 수 있다. 폭이 모자라면 파일명만 말줄임으로 줄이고 조작 요소는 숨기지 않는다.
- **배율:** 50~400%. 기본은 폭 맞춤이다. 슬라이드처럼 가로로 긴 쪽이 세로로 넘치면 쪽 맞춤으로 시작한다 [제안]. 배율은 문서별로 복원한다 [제안].
- **쪽 번호:** 3.2절을 따른다.
- **PDF 안의 링크:** 내부 링크는 해당 쪽으로 이동한다. 외부 링크는 열지 않고 주소만 보여 준다 [제안]. 악성 PDF의 외부 탐색을 막는 앱 정책(`docs/architecture.md` 1절)과 맞추기 위함이다.

## 3. 공통 개념

세 정의가 뷰어, 전송 범위, 쪽 근거, 이해도 확인에 함께 쓰인다.

### 3.1 현재 쪽

연속 스크롤에서는 두 쪽이 함께 보일 수 있으므로 현재 쪽을 하나로 정한다.

- **현재 쪽은 뷰어 세로 중앙선에 걸린 쪽이다.** 중앙선이 쪽 사이 틈에 있으면 위쪽 쪽으로 본다.
- 표시 갱신은 스크롤이 멈춘 뒤 150ms 지연해 깜빡임을 막는다. 전송 시점에는 지연 없이 그 순간의 값을 계산한다.
- 도구 막대의 쪽 번호, 범위 표시, 입력창 안내 문구가 모두 이 값을 쓴다.

### 3.2 쪽 번호

- **앱의 모든 쪽 번호는 PDF 파일의 물리적 순번(1부터)이다.** 논문의 인쇄 쪽 번호(예: 235)와 다를 수 있다.
- 튜터가 근거로 표시하는 번호도 같은 체계여야 한다. 모델에 쪽을 전달할 때 이 번호를 붙여 보낸다.
- 표기는 화면 전체에서 `p.12`, 범위는 `p.11~13`으로 통일한다.

### 3.3 전송 범위 스냅샷

보내기를 누른 순간의 범위를 하나의 값으로 고정한다. 화면 표시와 실제 요청을 **같은 값**으로 만든다. 표시용 문자열을 따로 계산하지 않는다. `docs/architecture.md` 4절에 따라 **범위는 메인 프로세스가 확정**한다. 렌더러는 기준 쪽과 선택을 알리고, 메인이 확정해 돌려준 값을 표시한다.

| 필드 | 뜻 |
|---|---|
| 기준 쪽 | 선택이 있으면 선택이 있는 쪽, 없으면 현재 쪽 |
| 쪽 범위 | 기준 쪽과 앞뒤 1쪽. 문서 경계에서 잘린다(첫 쪽 `p.1~2`, 한 쪽 문서 `p.1`). 앞뒤 쪽 수는 설정값으로 둔다 [품질 확인] |
| 쪽 형식 | 쪽별 텍스트 또는 이미지 [품질 확인] |
| 선택 | 없음, 텍스트(내용과 쪽), 영역(이미지와 쪽). 최대 1개 |
| 이전 대화 | 포함한 턴 수와, '잘못 읽음'으로 고친 내용 |
| 제공사, 모델 | `OpenAI`, 모델명 [품질 확인] |

**규칙**

- 전송 뒤 스크롤하거나 선택을 바꿔도 진행 중인 요청과 이미 보낸 메시지의 범위는 바뀌지 않는다.
- 내 질문 아래에 보낸 범위를 함께 적는다("보낸 범위: p.11~13 · 선택 영역 1개"). 대화를 저장할 때 함께 저장한다.
- 문서 전체는 어떤 경로로도 보내지 않는다.

## 4. 화면과 상태

### 4.1 상태 지도

서로 독립인 세 축의 조합으로 화면을 그린다. 축마다 상태를 하나의 값으로 관리한다.

| 축 | 상태 |
|---|---|
| 문서 | 없음 → 여는 중 → 열림 / 열 수 없음 |
| 키 | 없음 ↔ 있음. 설정 화면에서 입력·검증·삭제 |
| 대화 턴 | 대기 → 전송 중(첫 글자 전) → 스트리밍 → 완료 / 중지됨 / 오류 |

이해도 확인은 대화 턴 위에 얹는 입력 모드다(4.9절). 진단은 문서 열림의 속성이다(4.4절).

### 4.2 문서 없음

- **뷰어:** 가운데에 "PDF를 여기에 끌어다 놓거나 열어 주세요"와 [PDF 열기](`⌘O`). 창 전체가 끌어 놓기 대상이다. 끌어 올리면 테두리로 표시하고, PDF가 아니면 "PDF 파일만 열 수 있습니다"를 보여 준다.
- **패널:** 펴진 상태로 "문서를 열면 지금 보는 쪽을 함께 보며 답합니다"를 보여 준다. 범위 표시와 입력창은 없다.
- **최근 문서:** [PDF 열기] 아래에 최근 문서 최대 8개를 파일명과 날짜로 표시하고, 누르면 바로 연다. 없으면 표시하지 않는다(2026-11-05 사용자 요청. 이전의 '화면에 넣지 않는다' 제안을 대체한다).
- **첫 실행:** 환영 화면, 기능 소개, 동의 절차가 없다. 곧바로 이 상태로 시작한다.
- **재실행:** 마지막 문서가 그대로 있으면 자동으로 열고 읽던 쪽으로 간다 [제안]. 없으면 이 상태로 시작해 "이전 문서를 찾을 수 없습니다"를 잠시 표시한다.

### 4.3 문서 여는 중과 열 수 없음

- **여는 중:** 1초가 넘으면 뷰어에 진행 표시를 띄운다. 기존 문서가 열려 있었다면 새 문서가 열린 뒤에 교체한다.
- **손상된 PDF:** "이 파일은 손상되어 열 수 없습니다." 암호 PDF: "암호가 걸린 PDF는 열 수 없습니다." 크기 제한 초과: "파일이 너무 커서 열 수 없습니다." 앱은 종료되지 않고 이전 화면이 유지된다. 암호 입력란을 두지 않고 해제를 시도하지 않는다(decisions).
- **다른 문서 열기:** 현재 문서를 대체한다. 진행 중인 답변은 중지하고 받은 부분까지 저장한다. 입력 중인 질문은 문서별로 보관한다 [제안]. 확인 대화상자는 없다.

### 4.4 문서 열림과 진단 경고

**기본:** 뷰어에 문서가 표시되고, 패널에 대화 복원 내용 또는 빈 대화 안내가 보인다. 빈 대화 안내 문구: "막히는 곳을 질문하거나, 수식과 도표를 끌어서 선택해 물어보세요." 전체 요약이나 문서 Q&A를 떠올리게 하는 예시를 쓰지 않는다.

**진단:** 첫 쪽 표시를 막지 않는다. 진단은 뒤에서 실행하고, 끝나면 결과를 표시한다.

| 진단 결과 | 뷰어 상단 배너 | 튜터 | 선택 |
|---|---|---|---|
| 정상 | 없음 | 정상 | 기본 규칙 |
| 텍스트 층 없음(스캔) | "스캔 문서로 보이며 정확도가 낮을 수 있습니다. 궁금한 부분을 끌어서 선택해 보세요." | 쪽 이미지로 답함 | 드래그가 곧 영역 선택 |
| 텍스트 층 깨짐 | "이 문서의 글자 정보가 깨져 있어 정확도가 낮을 수 있습니다. 궁금한 부분을 끌어서 선택해 보세요." | 쪽 이미지로 답함 | 기본 규칙. 텍스트 선택 칩에 경고(5.6절) |
| 지원 범위 밖 [품질 확인] | "이 유형의 문서는 현재 튜터 지원 범위가 아닙니다. 읽기는 계속할 수 있습니다." | 입력 불가. 사유 표시 | 텍스트 선택만 |
| 복사 금지(decisions) | "이 문서는 복사 금지로 설정되어 AI로 보내지 않습니다. 읽기는 계속할 수 있습니다." | 입력 불가. 사유 표시 | 읽기 가능. 텍스트 복사는 14.2절 2번 |

**배너 규칙**

- 뷰어 맨 위, 도구 막대 아래에 붙으며 쪽을 가리지 않고 뷰어 영역을 민다. 모달이 아니다.
- 한 줄 경고이며(`docs/tasks.md` 6단계) 닫을 수 있다. 문서를 다시 열면 다시 표시한다.
- 일부 쪽만 스캔인 혼합 문서는 문서 단위로 한 줄만 경고한다. 선택 동작은 쪽마다 텍스트 층 유무를 따른다(5.1절).
- 스캔본 지원(F13)을 축소하면 스캔 행은 '지원 범위 밖' 행으로 바뀐다.

### 4.5 키 설정

키 입력, 검증, 삭제만 있는 단순한 화면이다. 단계별 안내, 키 발급 설명, 비용·데이터 설명, 동의 절차를 두지 않는다.

**위치:** 설정 창(4.10절)의 첫 항목이다.

```text
API 키
상태: 저장됨
[ 새 키 입력                ] [확인하고 저장]
[키 삭제]
```

| 요소 | 규칙 |
|---|---|
| 상태 | "없음" 또는 "저장됨"만 표시한다. 키 값과 마스킹한 일부를 표시하지 않는다 |
| 입력란 | 비밀번호형, 항상 표시. 공백은 앞뒤를 제거한다. 저장된 키가 있을 때 새 키를 저장하면 교체된다 |
| [키 삭제] | 키가 저장되어 있을 때만 표시. 앱 전체를 막지 않는 설정 창의 확인 대화상자를 거친다 |

**검증 결과**

입력란 아래에 표시한다.

| 결과 | 표시 | 다음 |
|---|---|---|
| 검증 중 | 버튼이 "확인 중…"으로 바뀌고, 입력란 비활성 | |
| 성공 | "키를 저장했습니다." | 입력란을 비우고 상태를 "저장됨"으로 변경 |
| 잘못된 키 | "키를 인식하지 못했습니다." | 입력란 포커스 |
| 잔액·한도 부족 | "키는 맞지만 OpenAI 잔액이나 한도가 부족합니다." | 저장 여부는 검증 방식 확정 때 정한다 |
| 네트워크 문제 | "인터넷에 연결되지 않아 키를 확인하지 못했습니다. 키는 저장되지 않았습니다." | [확인하고 저장] 다시 누르기 |
| 키 저장 실패 | "macOS 보안 저장소에 키를 저장하지 못했습니다." 평문 저장으로 대체하지 않는다(`docs/architecture.md` 3절) | [확인하고 저장] 다시 누르기 |

**키 없이 질문을 보낼 때**

1. 키가 없어도 문서 열기, 읽기, 선택, 질문 입력은 모두 된다. 앱 실행이나 문서 열기만으로 키 안내를 띄우지 않는다.
2. 보내기를 누르면 아무것도 전송하지 않는다. 질문과 선택은 입력 블록에 그대로 남고, 입력창 바로 위에 "API 키가 없습니다. [키 설정]"이 표시된다. [이해도 확인]과 [다시 보내기]를 눌렀을 때도 같다.
3. [키 설정]은 설정 창을 열고 입력란에 포커스를 둔다. 뷰어는 막히지 않는다.
4. 저장에 성공해 설정 창을 닫으면 입력창으로 포커스가 돌아온다. **자동 전송하지 않으며**, Enter를 누르면 그때의 범위로 전송된다(14.2절 1번).

**구현 주의**

- 키는 입력 후 메인 프로세스로 한 번 넘기고 입력란을 즉시 비운다(`docs/architecture.md` 3절). 렌더러 전역 상태, 저장소, 로그, 오류 메시지에 넣지 않는다.
- **저장된 키를 읽지 못하는 경우:** 애드혹 서명 빌드는 새 빌드 설치 후 복호화에 실패할 수 있다(`docs/architecture.md` 6절). 키 없음으로 처리하고 설정 창 상태에 "저장된 키를 읽지 못했습니다. 다시 입력해 주세요."를 표시한다.
- 키 목록 조회처럼 과금 없는 검증은 잔액 부족을 잡지 못할 수 있다. 검증을 통과했어도 답변에서 잔액 부족이 나올 수 있으므로, 이 경우 4.11절의 오류 흐름으로 처리한다. 검증 방식은 `docs/tasks.md` 3단계에서 확정한다.

### 4.6 답변 스트리밍

| 상태 | 대화 영역 | 입력 블록 |
|---|---|---|
| 전송 중(첫 글자 전) | 내 질문, 보낸 범위, "p.12를 읽는 중…" | 입력 가능, [보내기] 자리에 [중지] |
| 15초 초과 | "평소보다 오래 걸리고 있습니다"를 추가 [제안] | 같음 |
| 60초 초과 | 시간 초과 오류로 전환 [제안] | 질문 유지, 재시도 |
| 스트리밍 | 받은 내용을 차례로 표시 | 입력 가능, [중지] |
| 완료 | 근거 라벨, 이해도 확인 제안 표시 | [보내기] |
| 중지됨 | 받은 부분 유지, "중지됨" 표시, [다시 보내기] | [보내기] |

**규칙**

- 한 번에 한 턴만 진행한다. 스트리밍 중에도 다음 질문을 **입력**할 수 있지만 보낼 수는 없다. 이때 Enter는 아무 일도 하지 않고 줄바꿈도 넣지 않으며, 입력 내용은 그대로다. 대기열이 없다.
- **중지:** [중지] 버튼 또는 `⌘.`. Esc로는 중지하지 않는다. Esc는 한글 입력이나 선택 해제에도 쓰이기 때문이다.
- **자동 스크롤:** 사용자가 맨 아래에 있을 때만 따라간다. 위로 스크롤하면 멈추고 [맨 아래로] 버튼을 띄운다. '잘못 읽음' 입력 중에는 자동 스크롤을 멈춘다.
- **포커스:** 스트리밍이 포커스를 가져가지 않는다. 전송 뒤 포커스는 입력창에 남는다.
- **뷰어 독립:** 답변을 받는 동안 쪽 이동, 선택, 패널 접기가 모두 가능하다. 새 선택은 다음 질문부터 적용되며, 진행 중인 답변의 스냅샷은 바뀌지 않는다.

**수식 표시(F2)**

- 닫는 기호가 오지 않은 수식은 원문을 보여 주지 않고 자리표시를 유지하다가, 완성되면 수식으로 바꾼다.
- 완성 뒤에도 렌더링에 실패하면 원문 코드를 고정폭으로 표시하고 "수식을 표시하지 못했습니다"를 덧붙인다. 조용히 깨진 문법을 노출하지 않는다.
- 수식이 패널보다 넓으면 수식만 가로 스크롤한다. 대화 영역 전체가 가로로 밀리지 않는다.
- **배포 빌드에서 시험한다.** 배포 CSP는 `style-src 'self'`로 인라인 스타일을 막지만 개발 CSP는 허용한다. HTML 문자열에 `style` 속성을 넣는 수식 렌더러는 개발 환경에서만 멀쩡해 보일 수 있다.

**답변 내용의 안전한 표시(PRD 12절)**

- 제목, 목록, 강조, 코드, 수식만 렌더링한다. HTML, 이미지, 원격 리소스는 렌더링하지 않는다.
- 답변 안의 주소는 일반 글자로 표시하고 클릭되지 않게 한다 [제안].

### 4.7 읽은 내용 되짚기와 '잘못 읽음'

**언제 보이나**

| 질문 | 되짚기 |
|---|---|
| 영역 선택 질문 | 항상 표시 |
| 수식이 포함된 텍스트 선택, 또는 수식·도표를 묻는 쪽 질문 | 모델이 판독에 의존한 경우 표시 [품질 확인] |
| 그 밖의 질문 | 표시 안 함 |

**표시**

- 답변 맨 앞에 "읽은 내용" 라벨이 붙은 블록을 놓고 수식은 렌더링해 보여 준다.
- 모델이 불확실하다고 한 부분은 점선 밑줄과 함께 글자로 "(불확실)"을 붙인다. 색만으로 구분하지 않는다.
- 블록 안의 [잘못 읽음] 버튼은 되짚기 내용이 나타나는 순간부터 누를 수 있다.

**답변은 멈추지 않고 이어진다.** 되짚기를 보여 준 뒤 사용자 확인을 기다리지 않고 답변 스트리밍을 계속한다(12절 판단 3).

**'잘못 읽음' 수정 흐름**

1. [잘못 읽음]을 누르면 블록 안에 입력란이 열리고 포커스가 옮겨 간다. 진행 중인 스트리밍은 계속된다. 취소해도 잃는 것이 없게 하기 위함이다.
2. 입력란은 **평소 말로 고치는 칸**이다. 안내 문구: "맞는 내용을 적어 주세요. 예: 첨자가 i가 아니라 j입니다." LaTeX를 미리 채워 넣지 않는다. 수식 문법을 쓰지 않고 빠르게 고칠 수 있어야 한다.
3. 입력란 아래에 "같은 범위(p.11~13 · 선택 영역 1개)로 OpenAI에 다시 보냅니다"를 표시한다.
4. [고쳐서 다시 답변]을 누르면 진행 중인 스트리밍을 중지하고 새 답변을 요청한다. 키 입력 규칙과 Enter 처리는 입력창과 같다(7.3절). [취소]나 Esc를 누르면 닫는다.
5. 새 답변의 되짚기 블록에는 "내가 고친 내용"을 함께 표시한다. 이전 답변은 "고치기 전 답변"으로 접어 대화에 남긴다.
6. 고친 내용은 이후 후속 질문에 **항상** 포함한다. 대화 일부만 보낼 때 잘려 나가지 않아야 한다(US-4). 범위 자세히 보기에 "내가 고친 내용 n건"으로 표시한다.

### 4.8 쪽 근거

- **문서 근거:** 해당 문단 끝에 `근거 p.12` 라벨을 붙인다.
- **일반 지식:** 해당 문단 끝에 `일반 지식` 라벨을 붙인다. 근거 라벨과 글자와 모양 모두 다르게 해 색만으로 구분하지 않는다.
- **답변 끝 요약:** "근거: p.12, p.13 · 일반 지식 포함". 스트리밍 중에는 문단이 끝날 때 라벨을 붙이고 완료 후 요약을 표시한다.
- **근거 라벨을 누르면 해당 쪽으로 이동한다(decisions).** 답변 문단 라벨, 답변 끝 요약, 이해도 확인 카드에 모두 적용한다. 스크롤만 하고 AI를 호출하지 않는다. 포커스는 라벨에 남기고, 범위 표시는 현재 쪽 규칙(3.1, 5.4절)에 따라 바뀐다. `일반 지식` 라벨은 누를 수 없다.
- **검증:** 해당 턴과 포함된 이전 대화에서 보낸 범위 밖의 쪽 번호는 근거 라벨로 만들지 않고 본문 글자로 둔다 [제안]. 지어낸 번호가 근거나 이동 버튼처럼 보이는 일을 막기 위해서다.

**범위 밖 질문(F5)**

- 답변 자리에 "이 쪽들만으로는 답할 수 없습니다. 내용이 있는 쪽으로 이동하거나 영역을 선택한 뒤 다시 물어보세요." 형태의 안내를 표시한다.
- 근거 없는 쪽 번호를 지어내지 않는다. 튜터는 보낸 범위 밖을 보지 못하므로 구체적 쪽을 추천할 수 없는 경우가 대부분이다(14.1절 3번).
- 안내 아래 [지금 쪽으로 다시 묻기] 버튼은 같은 질문을 입력창에 채운다. 쪽을 옮긴 뒤 사용자가 보내면 된다 [제안].
- 문서 전체를 묻는 질문에도 같은 형식으로 답하되 "문서 전체는 보내지 않습니다"를 덧붙인다.

**답변 바닥글(완료 후)**

`[p.12 이해도 확인]`을 놓는다.

### 4.9 이해도 확인

> **제거됨(2026-11-05, 사용자 결정, `docs/decisions.md`).** 아래 내용은 기록으로만 남긴다.

**시작**

| 경로 | 위치 | 기준 |
|---|---|---|
| 답변 끝 제안 | 답변 바닥글의 `[p.12 이해도 확인]`. 가장 최근 답변에만 표시. 버튼 옆에 보낼 범위를 글자로 표시("p.11~13 · OpenAI") | 그 답변의 스냅샷에서 쪽 범위와 선택을 그대로 사용 |
| 직접 시작 | 입력 블록 왼쪽 아래 [이해도 확인]. 문서가 열려 있으면 항상 표시 | 지금의 범위 표시 그대로(활성 선택 포함) |

쪽을 넘길 때 앱이 먼저 묻지 않는다. 능동 비서가 Non-goal이고, 사용자의 키 비용을 쓰기 때문이다.

**입력 모드**

버튼을 누르면 곧바로 질문을 요청한다. 질문 카드가 대화 흐름에 들어오고 입력 블록이 답변 모드로 바뀐다.

```text
| 이해도 확인 1/2 · p.12 기준           [그만하기] |
| 보낼 범위 p.11~13 · 이전 대화 일부 · OpenAI     |
| [ 내 말로 답을 적어 보세요            ]         |
|                                  [답 제출]     |
```

- 질문 수는 1~3개이며 모델이 쪽 내용에 맞게 정한다. 카드에 근거 쪽을 함께 표시한다(US-6).
- 이 모드에서 Enter는 답 제출이다. 일반 질문을 보내려면 [그만하기]를 눌러야 한다.
- 쪽을 옮겨도 모드가 유지되고 범위는 시작 시점으로 고정된다. 사용자가 앞 슬라이드를 다시 볼 수 있어야 한다.
- 진행 중에 새로 만든 선택은 이번 확인에 포함되지 않는다. 끝난 뒤의 일반 질문에 쓰이며, 칩 옆에 "다음 질문에 사용"으로 표시한다 [제안].

**채점**

| 결과 | 표시 | 다음 동작 |
|---|---|---|
| 맞음 | 글자 "맞음" + 아이콘, 이유, 근거 쪽 | [다음 질문] 또는 [마치기] |
| 부분 맞음 | 글자 "부분 맞음" + 아이콘, 맞은 부분과 빠진 부분 | [다시 답하기], [다음 질문] |
| 틀림 | 글자 "틀림" + 아이콘, 이유와 **힌트**. 정답은 숨김 | [다시 답하기], [정답 보기] |
| 다시 답해도 틀림 | 새 힌트 | 같음. [정답 보기]는 계속 사용자의 선택이다 |
| 정답 보기 | 정답, 이유, 근거 쪽 | [다음 질문] 또는 [마치기] |

- 정답을 자동으로 공개하지 않는다(US-6).
- 마지막에 요약 한 줄: "2문항 중 1문항 맞음 · 근거 p.12". 입력 블록이 일반 모드로 돌아간다.
- **끝나는 조건:** 모든 문항이 결과를 받거나 정답 보기까지 가면 끝난다(14.1절 4번). [그만하기], 문서 전환, 앱 종료는 그 자리에서 끝내고 대화에 "중단됨"으로 남긴다. 다시 열어도 이어서 진행하지 않는다 [제안].
- 질문 생성이나 채점이 실패하면 4.11절 흐름을 따르며, 적은 답은 입력창에 유지한다.

### 4.10 설정과 문서별 동작

`⌘,` 또는 패널 머리의 [설정]으로 여는 별도 창이다(버튼은 2026-11-05 사용자 요청으로 추가). 메인 프로세스가 만들고 본 창과 같은 보안 설정을 적용한다.

| 영역 | 내용 |
|---|---|
| API 키 | 입력, 검증, 삭제(4.5절) |
| 모양 | 시스템 따름, 라이트, 다크(9절). 튜터 글자 크기 3단계 [제안] |

패널 머리의 [...] 메뉴에는 **[이 문서의 대화 삭제]** 하나만 둔다(US-8). 앱 전체를 막는 확인 대화상자를 쓰며, 문구는 "이 문서의 대화를 삭제할까요? 되돌릴 수 없습니다."다. 대화 목록, 새 대화, 내보내기, 공유는 없다. 문서당 대화는 하나다.

**복원(F12)과 [이 문서의 대화 삭제]: 제거됨(2026-11-05, 사용자 결정, `docs/decisions.md`).** 이하는 기록이다. **복원(F12):** 재실행 시 문서별 읽던 쪽과 대화를 복원한다. 스크롤 위치는 맨 아래로 간다. 선택은 복원하지 않는다. 저장된 선택 표시가 하이라이트처럼 읽히지 않게 하기 위함이다.

### 4.11 오류 상태(PRD 흐름 4)

**공통 규칙**

- **위치:** 실패한 턴 바로 아래, 대화 영역 안에 표시한다. 모달과 사라지는 토스트를 쓰지 않는다.
- **질문 유지:** 질문과 스냅샷은 대화에 남는다. [다시 보내기]는 **실패 당시 범위**를 그대로 보내고 버튼 옆에 범위를 표시한다. [고쳐서 다시 묻기]는 질문을 입력창으로 옮기며 이때는 현재 범위를 쓴다 [제안].
- **받은 부분:** 답변 도중 실패하면 받은 부분을 "중단됨"과 함께 유지한다.
- **읽기 유지:** 어떤 오류도 뷰어를 막지 않는다.
- **원문 비노출:** 제공사의 원본 오류 응답을 화면과 로그에 그대로 남기지 않는다. 키 문자열이 섞일 수 있기 때문이다.

| 상황 | 판별 근거(구현 시 OpenAI 공식 문서로 확인) | 문구 초안 | 사용자 행동 |
|---|---|---|---|
| 잘못된 키 | 인증 실패(401) | "키가 올바르지 않거나 더 이상 쓸 수 없습니다." | [키 설정](4.5절), 저장 후 [다시 보내기] |
| 요청 한도 초과 | 한도 오류(429, 요청·토큰 속도) | "OpenAI의 요청 한도에 걸렸습니다. 앱이나 문서의 문제가 아닙니다. 잠시 후 다시 시도해 주세요." | 대기 후 [다시 보내기] |
| 잔액 부족 | 쿼터 오류(429, 잔액·쿼터) | "OpenAI 잔액이 부족합니다. 비용은 OpenAI에서 결제되며 앱과는 별개입니다." | OpenAI에서 충전 후 [다시 보내기], 또는 [키 설정] |
| 네트워크 끊김 | 연결 실패 | "인터넷에 연결되지 않았습니다. 문서 읽기와 저장된 대화 보기는 계속할 수 있습니다." | 연결 후 [다시 보내기] |
| 제공사 장애, 시간 초과 [제안] | 5xx, 60초 초과 | "OpenAI 응답을 받지 못했습니다. 질문은 그대로 있습니다." | [다시 보내기] |
| 스캔·깨진 문서 | 진단 결과 | 4.4절의 배너 문구 | 영역 선택 또는 다른 문서 |
| 지원 범위 밖 문서 | 진단 결과, 품질 확인 결과 | 4.4절의 배너 문구 | 다른 문서 |
| 범위 밖 질문 | 튜터 답변 | 4.8절의 안내 문구 | 쪽 이동 후 다시 묻기 |

PRD 흐름 4의 '무료 한도 초과'와 '유료 키'는 Gemini 무료 등급 기준이다. OpenAI가 첫 제공사이므로 이 계약은 '요청 한도 초과'로 바꾸어 적었다(14.1절 2번).

**아키텍처 연결:** 렌더러는 제공사 원문이 아닌 공통 오류 코드만 받는다(`docs/architecture.md` 4절). 위 표를 그리려면 공통 코드가 요청 한도 초과와 잔액 부족을 따로 구분해야 한다.

## 5. 텍스트 선택과 영역 선택

### 5.1 기본 규칙: 시작점이 정한다

별도 모드 전환 없이 **드래그를 시작한 지점**이 선택 종류를 정한다. 드래그 중에는 종류가 바뀌지 않는다.

| 시작 조건 | 결과 |
|---|---|
| `⌥` 누르고 드래그(어디서든) | 영역 선택 |
| 영역 모드에서 드래그(어디서든) | 영역 선택 |
| 시작점 8px 안에 텍스트 층의 글자가 있음 | 텍스트 선택 |
| 시작점 8px 안에 글자가 없음(그래프, 그림, 여백, 텍스트 층 없는 쪽) | 영역 선택 |

위에서부터 먼저 맞는 행을 적용한다.

**포인터 모양:** 글자 위에서는 I자형, 글자가 없는 곳과 영역 모드·`⌥`에서는 십자형이다. 드래그 전에 무엇이 일어날지 포인터로 예고한다.

**기본 수치:** 4px 미만 이동은 클릭으로 본다. 끝난 영역이 24×24px보다 작으면 버린다.

### 5.2 영역 모드

- 켜는 법: 도구 막대 [영역 선택], `⌘⇧R`, 또는 뷰어에 포커스가 있을 때 `R`.
- **1회용이다.** 선택 하나를 끝내면 자동으로 꺼진다. 다시 누르거나 Esc로도 끈다. 모드에 갇혀 텍스트를 선택하지 못하는 일을 막기 위해서다.
- 도구 막대 버튼은 켜진 상태를 표시하고(`aria-pressed`), 포인터가 십자형으로 고정된다.

### 5.3 선택 범위의 제한

- **선택은 한 쪽 안에서만 유효하다.** 끌다가 쪽 경계를 넘으면 시작한 쪽의 끝까지로 제한한다. 전송 범위가 선택 때문에 늘어나지 않게 하기 위함이다.
- **활성 선택은 최대 1개다.** 새 선택은 이전 선택을 대체한다. 텍스트와 영역을 함께 둘 수 없다.
- `⌘A`는 뷰어에서 현재 쪽의 글만 선택한다. 문서 전체 선택과 전송을 막기 위함이다.
- `⌘C`는 텍스트 선택에서 표준대로 동작한다. 복사만 하려고 선택해도 전송되지 않는다.

### 5.4 선택의 해제와 유지

브라우저의 기본 텍스트 선택은 입력창으로 포커스가 옮겨 가면 풀릴 수 있다. 그래서 선택이 끝나는 순간 내용과 위치를 앱 상태에 복사하고, 뷰어 위에 앱이 그린 표시를 유지한다.

| 사건 | 선택 |
|---|---|
| 입력창 클릭, `⌘L`, 패널 조작 | 유지 |
| 쪽 스크롤(전송 전) | 유지. 범위 기준이 선택 쪽에 고정되고 범위 표시에 알림(6.3절) |
| 칩의 [x], 뷰어 포커스에서 Esc, 페이지 빈 곳 단일 클릭 | 해제 |
| 새 선택 | 대체 |
| 전송 직후 | 유지. 후속 질문이 같은 수식을 이어 묻는 경우가 많다(시나리오 B) |
| 전송 후 현재 쪽이 선택 쪽을 벗어남 | 자동 해제. 범위가 현재 쪽 기준으로 돌아간다(US-3) |
| 다른 문서 열기, 앱 재실행 | 해제 |

선택 표시는 저장하지 않으며 주석이 아니다. 전송하는 영역 이미지에 앱의 선택 표시를 포함하지 않는다.

### 5.5 선택 후 흐름

| 종류 | 동작 |
|---|---|
| 영역 | 칩 생성, 패널이 접혀 있으면 펴기, **입력창으로 포커스 이동**. 영역 선택의 목적은 질문뿐이다 |
| 텍스트 | 칩 생성, 선택 끝 근처에 작은 [질문하기] 버튼 표시. 포커스는 옮기지 않는다. 복사하려는 사용자를 방해하지 않기 위함이다 |

[질문하기] 또는 `⌘L`을 누르면 입력창으로 이동한다. 버튼은 스크롤하거나 다른 곳을 누르면 사라지며, AI를 호출하지 않는다. 선택 칩은 남는다.

### 5.6 선택 칩

입력창 바로 위에 놓인다.

- **영역:** 실제 전송될 이미지의 썸네일 44px, "선택 영역 · p.12", [x].
- **텍스트:** 앞부분 두 줄 미리보기, "글자 수 · p.12", [x]. 사용자가 선택 내용을 확인할 수 있어야 한다(US-4).
- **깨진 텍스트 경고:** 텍스트 층 깨짐 판정 쪽이면 "글자가 깨졌을 수 있어요"와 [영역으로 바꾸기]를 보여 준다. 텍스트 선택을 둘러싼 사각형을 영역 선택으로 전환한다 [제안].

### 5.7 둘의 충돌 해결 요약

| 충돌 | 해결 |
|---|---|
| 그래프 안의 축 라벨에서 드래그 시작 | 글자 위이므로 텍스트 선택. 영역을 원하면 `⌥` 드래그나 영역 모드를 쓰거나, [영역으로 바꾸기]를 누른다 |
| 수식의 텍스트 층이 깨져 있는데 수식에서 시작 | 텍스트 선택 후 칩 경고로 안내한다 |
| 줄 왼쪽 여백에서 텍스트 선택을 시작 | 8px 안이면 텍스트, 그 밖이면 영역이 된다. 잘못 만들어져도 아무것도 전송되지 않으며 새로 드래그하면 대체된다. 직접 써 보고 판단한다(11절 G2) |
| 더블클릭, 트리플클릭 | 글자 위에서 단어, 줄 선택(표준). 이동이 없으므로 영역 선택과 충돌하지 않는다 |
| 기존 영역 위에서 드래그 | 항상 새 선택. 영역의 이동, 크기 조절 손잡이는 없다. 다시 그리면 된다 |
| PDF 링크 위 동작 | 클릭은 링크, 드래그는 표의 규칙 |

### 5.8 키보드로 영역 선택 [제안]

마우스 없이도 영역을 고를 수 있어야 한다(WCAG 2.2 끌기 대안). 영역 모드에서 Enter를 누르면 현재 쪽 가운데에 사각형이 나타난다. 방향키로 8px씩 이동, `⇧`+방향키로 크기 조절, Enter로 확정, Esc로 취소한다. 확정된 영역 크기와 위치를 스크린 리더로 알린다.

## 6. 전송 범위 표시

### 6.1 위치

**입력 블록의 맨 위, 입력창 바로 위에 항상 보인다.** 스크롤로 사라지지 않는다. 입력창 높이가 늘어나도 범위 표시는 줄지 않고 대화 영역이 줄어든다. 이해도 확인 답변 모드와 '잘못 읽음' 입력에도 해당 범위를 표시한다.

### 6.2 표시 내용

```text
보낼 범위  p.11~13 · 선택 영역 1개(p.12)        [자세히]
이전 대화 일부 포함 · OpenAI로 전송
```

- **1줄:** 쪽 범위, 선택 종류와 개수, 선택 쪽.
- **2줄:** 이전 대화 포함 여부, 제공사.
- **[자세히]** 는 위로 열리는 팝오버이며 Esc로 닫는다. 내용:
  - 쪽별 형식(텍스트, 이미지) [품질 확인]
  - 선택 미리보기
  - 포함한 이전 대화 턴 수와 내가 고친 내용 수
  - 제공사와 모델명
  - "문서 전체는 보내지 않습니다. 이 앱에는 별도 서버가 없고, 내 키로 OpenAI에 직접 보냅니다."

### 6.3 상태별 문구

| 상태 | 표시 |
|---|---|
| 쪽만, 첫 질문 | `보낼 범위 p.11~13` / `OpenAI로 전송` |
| 텍스트 선택 | `p.11~13 · 선택한 글 1개(p.12)` |
| 영역 선택 | `p.11~13 · 선택 영역 1개(p.12)` |
| 문서 경계 | `p.1~2`, 한 쪽 문서는 `p.1` |
| 선택 쪽과 현재 쪽이 다름 | 3줄째 추가: `선택 기준입니다. 지금 보는 p.20은 보내지 않습니다.` 강조 표시 |
| 키 없음 | 평소와 같음. [자세히]에 "키를 설정하기 전에는 아무것도 보내지 않습니다" 추가 |
| 전송 중 | 입력 블록의 범위는 **다음 질문**의 범위다. 진행 중인 턴의 범위는 내 질문 아래에 표시 |
| 이해도 확인 중 | `이해도 확인 1/2 · p.12 기준`과 고정된 범위 |
| 전송 차단 문서 | `이 문서는 AI로 보내지 않습니다` |
| 문서 없음 | 표시 안 함(입력창도 없음) |

### 6.4 범위 변경 알림

- 쪽 이동이나 선택으로 범위가 바뀌면 값이 바뀌는 칸을 잠깐 강조한다(동작 줄이기 설정 시 생략).
- 스크린 리더에는 스크롤이 멈춘 뒤 한 번만 변경을 알린다. 입력 중에는 알리지 않고, 입력창 설명(`aria-describedby`)으로 현재 범위를 연결한다.
- **전송 전 확인 단계는 없다.** 표시가 언제나 보이므로 추가 클릭을 요구하지 않는다.

## 7. 키보드, 포커스, 한글 입력

### 7.1 단축키

모든 앱 단축키는 macOS 메뉴에 등록해 메뉴에서 찾을 수 있게 한다. 개발용 기본 메뉴(강제 새로고침 `⌘⇧R`, 개발자 도구)는 배포 빌드에서 제거한다.

| 동작 | 키 | 메뉴 |
|---|---|---|
| PDF 열기 | `⌘O` | 파일 |
| 창 닫기, 앱 종료 | `⌘W`, `⌘Q` | 파일, 앱 |
| 설정 | `⌘,` | 앱 |
| 복사, 전체 선택, 잘라내기, 붙여넣기, 실행 취소 | 표준 | 편집 |
| 질문 입력으로 이동 | `⌘L` | 튜터 |
| 답변 중지 | `⌘.` | 튜터 |
| 패널 접기·펴기 | `⌃⌘S` | 보기 |
| 영역 선택 | `⌘⇧R`, 뷰어 포커스에서 `R` | 보기 |
| 확대, 축소, 폭 맞춤 | `⌘+`, `⌘-`, `⌘0` | 보기 |
| 전체 화면 | `⌃⌘F` | 보기 |
| 쪽 번호로 이동 | `⌥⌘G` | 이동 |
| 이전 쪽, 다음 쪽 | 뷰어 포커스에서 `←`/`→`, `PageUp`/`PageDown` | 이동 |
| 첫 쪽, 끝 쪽 | 뷰어 포커스에서 `Home`/`End` | 이동 |
| 스크롤 | 뷰어 포커스에서 `↑`/`↓`, `Space`, `⇧Space` | |
| 보내기 | 입력창에서 `Enter` | |
| 줄바꿈 | 입력창에서 `⇧Enter` | |

**한글 입력기 주의:** 수정 키 없는 단일 문자 단축키(`R`)는 `event.key`가 아니라 `event.code`(`KeyR`)로 판별한다. 한글 입력 상태에서는 `event.key`가 다른 값이 된다. 또한 입력란에 포커스가 있을 때는 동작하지 않는다.

### 7.2 Esc 처리 순서

위에서부터 먼저 해당되는 것 하나만 처리한다.

1. 한글 등 조합 중이면 앱은 처리하지 않는다.
2. 드래그 중인 선택 취소.
3. 열린 팝오버, 메뉴 닫기.
4. '잘못 읽음' 입력 닫기.
5. 영역 모드 끄기.
6. 뷰어에 포커스가 있으면 활성 선택 해제.

입력창의 Esc는 질문을 지우지 않는다.

### 7.3 한글 조합 중 Enter 처리

**요구 결과**

| 상황 | 결과 |
|---|---|
| `안녕하세` 입력 뒤 `요` 조합 중 Enter | **Enter 한 번으로 `안녕하세요` 전체가 1회 전송된다.** 마지막 글자가 빠지거나 다음 입력으로 남지 않는다 |
| 조합 중 `⇧Enter` | 글자 확정 뒤 줄바꿈 |
| 조합 중 Enter를 빠르게 연타 | 1회만 전송. 전송 직후 입력창이 비어 있어 뒤따르는 Enter는 무시 |
| 전송 뒤 | 입력창이 비고, 조합 찌꺼기가 다시 나타나지 않는다 |
| 답변 진행 중 조합 Enter | 글자는 확정되고 입력창에 남으며 전송되지 않는다 |
| 일본어·중국어 등 후보 확정이 필요한 조합 | Enter는 확정만 하고 전송하지 않는다. 한 번 더 눌러야 전송 |

한국어 사용자는 글자 조합을 '입력 중'으로 의식하지 않으므로, 두 번 눌러야 보내지면 앱이 고장 난 것으로 느낀다. 그래서 한글에 한해 확정과 전송을 한 동작으로 묶는다.

**구현 규칙**

1. `keydown`에서 Enter이고 `isComposing`이 참이거나 `keyCode`가 229이면 바로 전송하지 않고 '전송 대기'를 표시한다.
2. `compositionend`에서 확정 문자가 한글이면, 입력값이 갱신된 뒤 전송 대기를 실행한다. 한글이 아니면 전송 대기를 취소한다.
3. 전송 대기를 실행한 직후 뒤따라오는 같은 Enter `keydown`은 무시한다.
4. 전송은 입력창이 차 있고 진행 중인 턴이 없을 때만 실행한다. 공백만 있으면 보내지 않는다.

macOS와 Chromium의 이벤트 순서는 버전에 따라 다를 수 있으므로 코드로 가정하지 말고 실제로 시험한다.

**필수 시험:** macOS 기본 2벌식, 3벌식 조합으로 위 표 전체. 끝글자 받침 있음(`값`)과 없음(`요`), 전송 후 곧바로 이어 입력, 붙여넣기 후 Enter. 이 규칙은 질문 입력창, 이해도 확인 답, '잘못 읽음' 입력에 공통으로 적용한다. 공용 입력 컴포넌트 하나로 구현한다.

### 7.4 포커스 순서

`Tab` 순서는 다음과 같다.

1. 도구 막대: 이전·다음 쪽 → 쪽 번호 → 축소·배율·확대 → 폭 맞춤 → 영역 선택 → 패널
2. 진단 배너(있을 때)
3. 뷰어 페이지 영역(`tabindex="0"`, 방향키 스크롤)
4. 구분선
5. 패널 머리 메뉴
6. 대화 영역: 메시지 안의 동작 버튼을 대화 순서대로
7. 입력 블록: [자세히] → 칩 [x] → 입력창 → [이해도 확인] → [보내기]/[중지]

**포커스 이동 규칙**

| 사건 | 포커스 |
|---|---|
| 앱 시작, 문서 없음 | [PDF 열기] |
| 문서 열림 | 뷰어 페이지 영역 |
| `⌘L` | 입력창(패널이 접혀 있으면 펴고 이동) |
| 영역 선택 완료 | 입력창 |
| 질문 전송 | 입력창 유지 |
| [키 설정] | 설정 창의 키 입력란 |
| 설정 창 닫기 | 이전 포커스(질문 중이었다면 입력창) |
| 잘못된 키 | 키 입력란, 오류는 `aria-describedby`로 연결 |
| 이해도 확인 질문 도착 | 입력창 유지, 질문을 스크린 리더로 알림 |
| 근거 라벨 누름 | 라벨에 유지, 뷰어만 이동 |
| 팝오버, 메뉴 닫기 | 연 버튼 |
| 패널 접기 | [패널] 버튼 |
| `F6` | 뷰어 ↔ 패널 입력창 ↔ 도구 막대 순환 [제안] |

**빠른 흐름:** 키보드 사용자의 주 경로는 쪽 읽기 → `⌘L` → 질문 Enter → 답 읽기 → 뷰어 클릭 또는 `F6`이다.

### 7.5 macOS 관례

- **창:** 기본 제어 버튼과 통합 제목 막대를 쓴다. 도구 막대를 끌어 창을 옮기고, 더블클릭은 시스템 설정을 따른다. 뷰어와 패널 스크롤은 시스템 관성과 스크롤 막대 설정을 따른다.
- **앱 수명:** `⌘W`로 창을 닫아도 앱은 Dock에 남고, Dock 클릭으로 창이 다시 열린다. `⌘Q`에서 저장을 끝낸다.
- **메뉴:** 앱, 파일, 편집, 보기, 이동, 튜터, 윈도우, 도움말. 표준 편집 메뉴를 넣어야 입력란에서 복사·붙여넣기가 동작한다.
- **파일:** 표준 열기 대화상자, Finder에서 끌어 놓기, 최근 항목 메뉴. Finder의 '다음으로 열기' 연결 [제안].
- **문구:** 메뉴와 버튼 문구는 한국어로 쓰고, 메뉴에는 macOS 표준 단축키 기호를 사용한다.
- **확대:** 트랙패드 핀치로 뷰어 배율 조절. 창 전체 확대가 아니라 뷰어에만 적용한다.

## 8. 접근성 기준

**기준:** 앱 화면과 튜터 패널은 WCAG 2.2 AA를 목표로 한다 [제안]. PDF 본문의 스크린 리더 접근성은 문서의 텍스트 층에 달려 있으며, 스캔본은 본문을 읽어 줄 수 없다.

| 영역 | 기준 |
|---|---|
| 키보드 | 모든 기능을 키보드로 쓸 수 있다. 영역 선택도 대안을 둔다(5.8절) |
| 포커스 표시 | 모든 조작 요소에 2px 포커스 링, 대비 3:1 이상. 페이지 위에서도 보여야 한다 |
| 대비 | 본문 4.5:1, 큰 글자와 UI 경계 3:1 이상. 라이트와 다크 각각 측정 |
| 조작 크기 | 포인터 대상 최소 24×24px, 기본 28×28px |
| 색 의존 금지 | 근거/일반 지식, 맞음/부분 맞음/틀림, 불확실, 오류는 글자나 모양을 함께 쓴다 |
| 동작 줄이기 | `prefers-reduced-motion`에서 강조 효과와 전환을 없앤다. 스트리밍 커서는 깜빡이지 않는다 |
| 고대비 | `prefers-contrast`와 시스템 투명도 줄이기 설정에서 경계를 강화한다 |
| 글자 크기 | 패널 글자는 `rem` 기준으로 설정의 3단계(100, 125, 150%)를 따른다 [제안]. 200% 요구는 직접 써 보고 판단한다 |

**VoiceOver**

| 요소 | 처리 |
|---|---|
| 패널과 뷰어 | `role="region"`과 "PDF 뷰어", "튜터" 이름 |
| 대화 영역 | `role="log"`. 스트리밍 중에는 토큰마다 읽지 않고, `aria-busy`를 유지하다가 **문단 단위로** 알린다 |
| 답변 완료, 오류 | `aria-live="polite"`로 알림. 키와 네트워크 오류는 `role="alert"` |
| 수식 | MathML 또는 읽을 수 있는 대체 텍스트 제공 |
| 선택 칩 | 영역 썸네일에 "선택 영역, 12쪽" 대체 텍스트 |
| 쪽 표시 | 쪽 번호 입력란에 "현재 12쪽, 전체 80쪽" 이름 |
| 근거 라벨 | 버튼 이름을 "근거 12쪽으로 이동"으로 한다(`p.12`를 그대로 읽지 않음) |

## 9. 라이트·다크 모드

- 기본은 시스템 설정을 따른다. 설정에서 시스템, 라이트, 다크를 고를 수 있다 [제안]. 시스템 변경은 재시작 없이 즉시 반영한다.
- 색은 CSS 변수의 의미 토큰만 쓰고 값을 직접 넣지 않는다. 적용 순서는 `:root`(라이트), `@media (prefers-color-scheme: dark)`의 `:root:not([data-theme="light"])`, `:root[data-theme="dark"]`이다.
- **PDF 쪽은 다크 모드에서도 원본 색 그대로 표시한다.** 색을 반전하면 그래프 범례나 표의 색이 달라져, 학습 내용을 해칠 수 있다. 뷰어의 쪽 바깥 배경과 도구만 어두워진다. 다크 읽기용 쪽 반전은 MVP에 넣지 않는다.
- **페이지 위에 놓이는 요소**(선택 표시, 영역 테두리, [질문하기] 버튼)는 앱 테마와 관계없이 흰 쪽과 어두운 스캔 쪽 모두에서 보여야 한다. 그래서 별도 토큰(`--color-page-selection-*`)을 둔다.
- 답변의 수식과 코드, 설정, 대화상자 모두 두 테마에서 점검한다. 수식의 글자색은 부모의 글자색을 따른다.

## 11. 직접 써 보고 판단할 항목

사용자가 자신의 강의자료와 논문으로 공부하면서 판단한다. 별도의 참가자, 설문, 지표는 없다. 불편하다고 판단한 항목만 오른쪽처럼 바꾼다.

| ID | 판단할 것 | 써 볼 상황 | 불편하면 바꿀 것 |
|---|---|---|---|
| G1 | 답변이 이어져도 되짚기의 오독을 알아챌 수 있는가 | 첨자가 많은 수식, 범례가 많은 그래프를 영역으로 질문 | 영역 질문에서 확인 후 답변을 시작하는 단계로 전환 |
| G2 | 시작점 규칙이 손에 익는가 | 그래프를 선택해 질문, 문장을 선택해 복사, 줄 여백에서 드래그 시작 | 명시적 도구 전환으로 변경 |
| G3 | 입력창 위의 범위 표시가 보내기 전에 눈에 들어오는가 | 쪽을 옮긴 뒤 바로 질문, 평소처럼 공부 | 위치나 시각적 무게를 재설계 |
| G4 | 선택 쪽 고정이 헷갈리지 않는가 | 선택한 뒤 앞쪽 정의를 보러 갔다가 질문 | 쪽 이동 시 바로 해제 |
| G5 | 전송 후 선택 유지가 후속 질문에 도움이 되는가 | 같은 수식을 이어서 묻기, 곧이어 무관한 질문 | 전송 후 자동 해제 |
| G6 | 평소 말로 고쳐서 오독이 충분히 바로잡히는가 | 첨자 오류를 말로 고치고 재답변 확인 | 판독 원문을 수정 가능한 형식으로 제공 |

| G9 | 답변 끝 이해도 확인 버튼을 실제로 누르게 되는가 | 시험 공부처럼 여러 쪽을 진행 | 위치와 문구 변경 |

| G11 | 다크 모드에서 원본 색 쪽이 눈에 부담되지 않는가 | 밤에 공부 | 쪽 반전 옵션 검토 |

## 12. 설계 판단과 이유

| # | 판단 | 이유 | 버린 대안 |
|---|---|---|---|
| 1 | 나란히 배치만 쓰고 최소 창을 800px로 고정 | 답을 읽으며 쪽을 보는 것이 핵심 가치다. 레이아웃 하나로 구현과 시험 비용을 줄인다 | 패널 겹침 모드: 쪽을 가리고 구현과 시험 비용이 늘어난다 |
| 2 | 범위 표시를 입력창 바로 위로 이동(PRD 그림과 다름) | 사용자가 보내는 순간에 시선이 있는 곳이다. 선택 칩과 범위를 함께 놓아 하나의 '보낼 묶음'으로 읽힌다 | 패널 맨 위: 대화가 길면 시선에서 멀어진다 |
| 3 | 되짚기를 차단 없이 보여 주고 답변을 이어 감 | 시나리오 B는 먼저 확인 후 묻는 흐름을 그리지만, 매번 확인을 요구하면 맞게 읽은 다수 경우에도 비용이 든다. 대신 [잘못 읽음]으로 바로 고치게 한다. **위험:** 틀린 답을 먼저 읽을 수 있다. decisions의 기본값이며, G1로 판단해 바꿀 수 있다 | 확인 게이트: 정확하지만 턴마다 한 단계가 늘어난다 |
| 4 | 시작점으로 선택 종류를 정함 | 그래프처럼 글자 없는 곳을 끌면 바로 영역이 된다. 대부분 모드 전환이 필요 없고, 스캔본도 같은 규칙으로 동작한다 | 도구 전환만 제공: 질문할 때마다 전환 단계가 늘어난다 |
| 5 | 활성 선택 1개, 한 쪽 안으로 제한 | 전송 범위 표시가 단순해지고, 전체 문서 전송 가능성을 차단한다 | 다중 선택: 와이어프레임의 '선택 1개'가 개수 표시를 암시하지만 근거가 없다 |
| 6 | 선택이 있으면 범위 기준을 선택 쪽으로 고정하고, 전송 후 쪽을 벗어나면 해제 | 앞 정의를 보러 갔다 돌아와 묻는 흐름을 살리면서 US-3의 '옮긴 쪽 사용'을 지킨다 | 스크롤 시 무조건 해제: 앞쪽을 참고하는 흐름이 끊긴다 |
| 7 | 키 설정을 설정 창의 입력·검증·삭제로 한정하고, 저장 후 자동 전송하지 않음 | 사용자 본인만 쓰므로 안내가 필요 없다. 전송은 범위 표시를 본 뒤 사용자가 누를 때만 일어난다 | 단계별 온보딩과 자동 전송: PRD 흐름 1의 방식이지만 개인용 범위에 과하다 |
| 8 | '잘못 읽음'을 평소 말로 입력 | 공부 중에 LaTeX를 쓰는 것은 번거롭다 | 판독 원문 수정: 수식 문법을 알아야 한다 |
| 9 | 근거 라벨을 눌러 해당 쪽으로 이동 | 답을 원문과 바로 대조할 수 있다. decisions의 기본값이며 PRD 7절의 1단계 배치보다 우선한다 | 글자 라벨만: 쪽 번호를 직접 입력해야 한다 |
| 10 | 한글은 Enter 1회로 확정과 전송 | 한글 사용자의 기대에 맞고 PRD의 "글자가 끊기거나 중복 전송되지 않음"을 충족한다 | 조합 중 Enter 무시: 두 번 눌러야 보내져 고장처럼 보인다 |
| 11 | 오류를 실패한 턴 아래에 유지 | 무슨 질문이 실패했고 무엇을 하면 되는지 한곳에서 보인다 | 토스트: 사라지고, 재시도 대상이 모호하다 |
| 12 | 다크 모드에서 쪽 색을 유지 | 색이 의미를 갖는 도표를 왜곡하지 않는다 | 자동 반전: 그래프 해석을 해칠 수 있다 |
| 13 | 이해도 확인을 쪽 이동에 연결하지 않음 | 요청 없는 호출은 비용과 능동 비서 범위 문제를 만든다(PRD 7절, 8.4절) | 쪽 넘김 시 제안 |

**범위를 줄일 때**

뷰어, 튜터, 선택 질문, 근거 쪽, 되짚기, 이해도 확인, 전송 범위, 세션 복원, 키보드와 한글 입력은 줄이지 않는다. 스캔본 지원(F13)을 줄이면 4.4절의 스캔 행을 지원 범위 밖으로 전환한다.

**P1 기능**(F14 비용 표시, F15 설명 수준, F16 문서 내 검색, F17 두 번째 제공사)의 자리는 이 계약에 없다. 여유가 생겨 착수할 때 이 문서에 배치를 추가한다.

## 14. PRD의 모호함과 필요한 결정

### 14.1 PRD에서 발견한 모호함과 이 계약의 처리

| # | 모호함 | 이 계약의 처리 | PRD 수정 필요 |

### 14.2 사용자가 결정할 사항

decisions가 근거 쪽 클릭 이동, 비차단 되짚기, 복사 금지·암호 PDF의 해제·전송 금지, 최소 창 800×600을 기본값으로 정했다. 이 항목들은 직접 써 보고 바꿀 수 있다(11절 G1, G8, G10). 남은 결정은 다음과 같다.

| # | 결정 | 이 계약의 기본값 | 시한 |
|---|---|---|---|
| 1 | 키 저장 후 입력창의 질문을 자동 전송할 것인가. PRD 흐름 1은 자동 전송이지만 단순한 설정 화면 지시에 맞추어 뺐다 | 자동 전송 안 함. 입력창에 질문을 유지. G7로 판단 | 3단계 전 |
| 2 | 복사 금지 문서에서 텍스트 선택·복사를 허용할 것인가. decisions는 전송 금지만 정했다 | 읽기 허용, 복사는 문서 권한을 따름 | 1단계 전 |
