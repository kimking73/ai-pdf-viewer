## 다음 세션 시작점 (2026-11-05 기준)

**위치:** 3단계 완료. 사용자가 실제 OpenAI 키로 재실행 후 키 유지, 영역 이미지 질문, [중지], 수식 표시를 확인했다(2026-11-05). 4단계는 사용자가 튜터 확인 완료로 판단했다. 모델은 임시값 `gpt-6-luna`를 유지한다. 5·6단계 코드를 구현했고 단위 테스트까지 통과했다. 최근 문서와 품질 배너를 앱에서 확인하는 일이 남았다.

**구현한 것:** `src/main/ai/`(키 저장, 키 검증, OpenAI·POSTECH AI 호출, 답변 형식 해석, 오류 구분), `⌘,` 설정 창, 쪽 글·선택 글·영역 이미지 전송, 실패별 문구.

**이어서 할 일(순서대로):**
1. 사용자가 `npm run dev`로 실행해 `⌘,`에서 OpenAI를 고르고 키를 저장한 뒤 실제 PDF로 질문한다. 키는 대화로 받지 않고 `.env`도 쓰지 않는다.
2. 재실행 후 키 유지, 키체인 권한 창, 스트리밍 형식, 근거 라벨, 영역 이미지를 확인한다. 전부 실제 호출로는 아직 확인하지 않았다.
3. 사용자가 "검사 돌려"라고 하면 `npm run test:e2e`, `npm run package:mac`, `npm run test:packaged`를 1회만 실행한다. E2E는 `AI_PDF_VIEWER_FAKE_PROVIDER=1`로 가짜 응답을 쓴다.
4. 수식·답변 서식(`tutor/answer-format.ts`, `tutor/AnswerText.tsx`)은 구현했고 단위 테스트만 통과했다. 실제 답변 화면과 배포판(CSP) 확인이 남았다.
5. 6단계 확인 뒤 7단계로 간다. 쪽 이미지 전송(스캔 문서)은 사용자 결정 대기다.

**검토에서 나온 판단(코드 판단이며 실행 확인은 하지 않음):**
- 간헐 실패 2건은 코드만으로 확정하지 못했다. 앱의 선택 로직이 끊는 경로는 찾지 못했고, 입력 전달 문제일 수 있다(추정). 마지막 실패 3건(11:39~11:41)에는 패널 테스트가 없고 영역 선택 실패가 있었다.
- `getContext` 실패는 `scripts/smoke-packaged.mjs`의 타이밍 문제일 가능성이 높다. 수정 후 실행하지 않아 미확인이고, `:214-231`에 같은 종류의 위험이 남아 있다.
- 차단 B1·B2, 중요 I1·I2·I3은 고쳤다. 단위 테스트는 B2·I3만 다루고, B1·I1·I2는 렌더러 코드라 아직 실행으로 확인하지 않았다.
- 사소 항목 중 문서 교체 순서, 빈 답변을 턴으로 세는 문제, [다시 보내기] 중복은 함께 고쳤다. 나머지는 기록하지 않았다.

**2026-11-05 창 검사 결과:** E2E 29개 중 27개 통과. 실패 1건은 낡은 API 목록(수정, 재실행 전), 1건은 구분선 드래그 끝값이 첫 이동값(396)에 머문 간헐 실패(원인 미확정). 텍스트 복사 테스트는 이번에 통과했다. 패키징 빌드 성공. `test:packaged`는 앱 기본, 암호·손상 PDF, 렌더링, 한글, JPEG 2000까지 통과하고 튜터 확인에서 실패했다. 가짜 응답을 기대하던 낡은 스크립트 때문이며, 키 없음 흐름 확인으로 고쳤고 재실행 전이다. 보안 정적 점검(위험 API, 전송 주소 2곳, 로그, 키 문자열)에서 문제를 찾지 못했다.

**2026-11-05 2차 창 검사:** `test:packaged` 전부 통과(300쪽 첫 쪽 81ms, 이미지 문서 302ms, `getContext` 실패 없음). E2E는 29개 중 26개 통과, 3건 실패: 구분선 드래그가 396에 멈춤, 영역 선택 뒤 칩이 남음(`e2e/tutor.e2e.ts:205`), 텍스트 드래그가 'Fixture page 1 m'에서 끊김. 재실행하지 않았고 원인은 미확정이다. 그 뒤 구분선 끌기를 창 수준 입력으로 바꿨다(재실행 전). 영역·텍스트 드래그는 사용자가 직접 확인하기 전까지 고치지 않았다. POSTECH AI는 사용자가 키를 재발급한 뒤로 미룬다.

**2026-11-05 3차 창 검사:** E2E 29개 전부 통과, `test:packaged` 전부 통과(300쪽 82ms, 이미지 문서 234ms). 구분선 수정 뒤 1회 결과다. 영역·텍스트 드래그는 코드를 고치지 않았는데 통과했으므로 간헐 실패가 해결되었다고 보지 않는다. 설치한 앱에서 수식과 키 저장 확인이 남았다.

**창이 뜨는 검사 규칙(사용자와 약속):** E2E와 패키징 앱 확인은 앱 창을 실제로 띄워 사용자 작업을 가린다. 사용자가 요청할 때만 1회 실행하고, 실패하면 재실행 없이 결과부터 보고한다. 이전 세션에서 에이전트가 같은 테스트를 약 100회 넘게 반복해 사용자가 중단시켰다.

**확인되지 않은 것:**
- 수정 후 E2E 전체 결과와 2단계 코드의 `test:packaged` 결과. 패키징 스모크에서 `Cannot read properties of null (reading 'getContext')` 실패가 나온 적 있고, 수정 여부를 재확인하지 못했다.
- 300쪽 첫 쪽 시간, 토큰 적용, 수식 표시. Frontend Developer가 최종 보고 없이 중지되었다.

**간헐 실패 2건(원인 미확정):**
- '텍스트를 끌어 선택하고 복사한다': 6번 중 3번 실패, 마우스 무시 설정 후 6번 중 1번 실패. 선택이 "Fixt", "Fixture p"처럼 중간에 끊긴다. 사용자의 실제 마우스 간섭은 구현 에이전트의 추정이다.
- '패널의 기본 상태와 폭, 접기, 구분선': 6번 중 1번 실패. 구분선 더블클릭 뒤 `aria-valuenow` 검사 부근이다.

**현재 파일 상태:**
- 커밋이 하나도 없다. 모든 파일이 untracked이고, 커밋은 사용자가 요청할 때만 한다.
- 2단계 구현 코드는 작성자 외 검토를 받지 않았다.
- `e2e/viewer.e2e.ts:35`, `e2e/tutor.e2e.ts:28`에 테스트 전용 `setIgnoreMouseEvents(true)`가 남아 있다. 앱 코드에는 영향이 없다.
- 복제 폴더 `out/preload 2`, `out/renderer 2`(빈 폴더), `node_modules 2`(376KB)는 사용자가 지우라고 할 때 내용을 확인하고 지운다. `.gitignore`의 `node_modules`는 `node_modules 2/`에 적용되지 않아 커밋 전에 처리해야 한다.
- 11:50 시점에 이전 빌드(10:54)의 패키징 앱(pid 60810)이 떠 있다. 현재 코드를 반영하지 않으므로 이 앱으로 2단계를 판단하지 않는다.

## 미룬 항목
- POSTECH AI(사용자 지시로 나중에 수정, 2026-11-05): 입구 인증은 통과하지만 형식과 무관하게 HTTP 200으로 `<div cls="error" attr="10000"></div>`를 돌려준다. 가짜 키는 HTTP 401 `Gateway authentication failed`다. 코드 뜻, 쓸 수 있는 에이전트, 입력 내용의 저장·학습 규칙을 학교에 확인해야 한다. 고칠 것: 인증을 통과하면 키를 저장, 스트리밍(`data: {"message", "is_sse_finished"}`) 적용, `files`의 이미지 전달 확인.
- 사용자 지시로 모든 기능 구현 후 마지막에 수정(2026-11-05): 간헐 실패 2건과 패키징 검사의 `getContext` 실패. 그 전까지 창이 뜨는 검사에서 이 항목들이 실패해도 진행을 막지 않고, 결과만 보고한다.
- 2단계 전체 검사 미완료(2026-11-04 11:41 사용자 지시로 중단). 마지막 완료 결과는 E2E 29개 중 3개 실패(26개 통과). 텍스트 복사와 패널 기본 상태 테스트에 간헐 실패가 남아 있고 원인은 미확정이다. Code Reviewer 검토도 하지 않았다.
- 사용자 지시로 나중에 수정: `npm run lint`가 `scripts/smoke-packaged.mjs:121,123`의 `requestAnimationFrame` no-undef로 실패한다. 앱 코드 오류는 아니다.
- 계약 [제안] 항목 중 미룬 것: 패널 폭·접힘 저장, `F6` 포커스 순환, 깨진 텍스트 칩 경고와 [영역으로 바꾸기](문서 진단 필요), 15초 안내. 60초 무응답은 제공사 오류로 처리한다.
- 1단계 Code Reviewer 검토와 300쪽 문서 시간 측정 결과 확인: 2단계 검토 때 함께 한다.
