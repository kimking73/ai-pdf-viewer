## 1. W1 사전 인터뷰 가이드

**형식:** 30분, 대면 또는 화상. **대상:** 대학(원)생 5명 내외, 비CS 3명 이상(제안값). Mac 보유는 조건이 아니다. Windows·iPad 사용자의 답도 데스크톱 전제(PRD 가정 A1)를 검증하는 데 필요하다.

**연결되는 PRD 항목:** 2절의 문제 가설, 인터뷰 필수 질문 중 세 가지(막혔을 때 한 일, 기기, 도구). 네 번째 필수 질문인 "앱을 다음에 언제 쓰겠는가"는 W4와 W6에서 묻는다.

세션 중에는 A3의 행동 순서, 시간, 참가자 표현을 그대로 적는다. 해석은 세션이 끝난 뒤 10분 안에 6.2절 양식으로 옮긴다. 참가자의 말은 고치지 말고 그대로 적으며, 기록에는 이름 대신 참가자 ID만 쓴다.

## 2. W1 키 발급 측정 절차

**목적:** 학생이 도움 없이 OpenAI 키 발급과 충전을 끝내는 데 드는 시간과 막히는 곳을 측정한다(H4 초기 신호, PRD 6.1). 앱은 쓰지 않으며, 앱 안내가 없는 상태의 기준선이다.

**형식:** 인터뷰가 끝난 뒤 별도로 최대 30분(제안값), 원하는 사람만. 측정 전에 인터뷰를 끝내야 참가자의 답이 키 경험에 영향받지 않는다.

> 끝까지 진행하면 OpenAI에 최소 5달러를 본인 카드로 선불 충전하게 됩니다. 이 돈은 참가자의 실제 비용입니다. 충전액은 환불되지 않고 1년 후 만료됩니다. [선택: 충전액은 팀이 돌려드립니다 / 충전액은 돌려드리지 않습니다] 조건은 [빈칸: 공식 페이지 재확인 날짜] 기준이고 바뀔 수 있습니다.
>
> 충전 없이 결제 화면 앞까지만 해 보셔도 되고, 진행 중 언제든 멈추셔도 됩니다. 멈추셔도 보상은 똑같습니다. 어떤 결과든 실패가 아니며, 측정 대상은 참가자가 아니라 절차의 어려움입니다.
>
> 카드 번호와 API 키는 저에게 보여 주지 마세요. 입력할 때 저는 화면에서 눈을 돌리고, 화면 공유 중이라면 공유를 끕니다. 만든 키를 저에게 전달하지 않으며, 키 값은 기록하지 않습니다. 계정과 키, 남은 잔액은 모두 본인 것이고 끝난 뒤 키를 지울 수 있습니다.

### 2.2 참가자가 고르는 측정 범위

참가자가 시작 전에 고르고, 진행 중 언제든 낮은 범위로 바꿀 수 있다. 진행자는 어떤 범위도 권하지 않는다.

| 범위 | 하는 일 | 측정되는 것 | 측정되지 않는 것 |
|---|---|---|---|
| 1. 충전 포함 | 계정부터 충전, 키 생성까지 실제로 진행 | 전체 시간, 카드 승인 결과, 포기 지점 | 없음 |
| 2. 충전 없이 | 결제 수단 입력 화면까지 간 뒤 입력하지 않고 멈춤. 충전 없이 가능한 범위의 키 생성 시도 | 충전 전까지의 시간과 막힌 지점. 카드 준비 상태(자기 보고) | 실제 카드 승인, 충전 시간. 충전 없이 키가 동작하는지 여부 |
| 3. 계정 만들지 않음 | 실제 시도 없이 2.5절 카드 질문과 자기 보고만 | 준비 상태, 거부 이유 | 시간, 막힌 지점 |

**해석:** 범위 1만 "키 설정 시간"에 넣는다(PRD 6.1은 실제 충전 포함을 요구한다). 범위 2는 "충전 전 구간 시간"으로 따로 적는다. 범위 3과 "왜 이 범위를 골랐는가"의 답도 장벽 신호로 기록한다. 충전 거부를 "제품에 관심 없음"으로 읽지 않는다.

### 2.3 진행

**준비:** 참가자 본인 기기와 브라우저, 타이머, 2.4절 양식. 먼저 사용자가 직접 따라가 아래 단계 순서를 실제 화면에 맞춘다. 단계의 순서와 본인 인증 요구 여부는 미확인이다.

**과제 카드**

```text
OpenAI API 키를 만들어 주세요. [선택: 5달러를 충전하고 / 충전 없이 결제 화면 앞까지 간 뒤]
키가 만들어진 화면까지 가면 끝입니다. 검색을 포함해 평소처럼 아무 방법이나 쓰셔도 됩니다.
하면서 드는 생각을 소리 내어 말씀해 주세요. 그만두고 싶으면 언제든 "그만"이라고 하세요.
```

**진행 규칙**

1. 시작 시점에 타이머를 켜고, 아래 단계마다 시각을 적는다. 고지 시간은 넣지 않는다.
2. 질문을 받으면 "평소라면 어떻게 하시겠어요?"라고만 답한다.
3. 참가자가 그만두거나 30분(제안값)이 되면 끝낸다. 단계와 이유를 먼저 기록한다.
4. 포기 후 원하면 도와줄 수 있다. 도움 후 완료는 "도움 완료"로 따로 적고 시간 측정에는 넣지 않는다.
5. 원격이면 화면 공유 없이 음성으로 말하며 진행한다. 결제와 키 단계에서는 어떤 경우에도 공유하지 않는다.
6. 화면 녹화는 하지 않는다. 키와 카드 정보가 찍힐 수 있기 때문이다.

### 2.5 해외 결제 카드 기록

API 충전에 해외 결제 카드가 필요한지는 미확인이다(PRD 16절). 카드 번호 없이 범위 1~3 모두에 묻는다.

| 항목 | 기록 |
|---|---|
| 지금 쓸 수 있는 본인 명의 카드 | 신용 / 체크 / 없음 |
| 해외 결제 가능 여부를 아는지 | 된다 / 안 된다 / 모름 |
| 없을 때 떠올리는 방법(참가자 표현) | 가족 카드, 발급 신청 등 |
| 실제 시도한 카드 종류(범위 1) | 신용 / 체크 / 기타 |
| 승인 결과 | 성공 / 실패 / 시도 안 함 |
| 실패 시 재시도 횟수와 화면 문구 요지 | 카드 정보 제외 |
| 해외 결제 설정을 바꿔야 했는지 | 예 / 아니요 / 모름 |
| 달러 결제, 수수료, 환율에 대한 우려 | 발언 그대로 |

**5명 내외의 결과로 "카드가 필요하다/필요 없다"고 일반화하지 않는다.** 승인 실패가 1건이라도 있으면 설치 안내서와 모집 글에 그 조건을 추가하고, 다른 카드 유형은 미확인으로 남긴다.

### 4.5 공통 대본

**사전 질문**

> Q1. 이번 주에 공부 중인 자료는 어떤 것인가요? 가장 최근에 막힌 곳은 어디였나요?
>
> Q2. 그때 실제로 무엇을 하셨나요? 쓰던 도구를 지금 본인 휴대폰이나 노트북으로 3분만 그대로 보여 주실 수 있나요?

평소 방식 재현은 참가자 본인 기기에서만 한다(경로 A). 팀 Mac에는 참가자 계정으로 로그인하지 않게 한다. 행동 순서와 걸린 시간을 적는다. 원치 않으면 말로 듣고 넘어간다.

**과제 전 안내(소리 내어 생각하기)**

> 지금부터 이 앱으로 공부하시는 것을 보겠습니다. 저를 도와주려 하지 마시고, 불편하면 그대로 말씀해 주세요. 앱이 잘못한 것이고 사용자가 잘못한 것은 없습니다. 제가 이 앱을 만들었지만 나쁜 얘기를 들어야 고칠 수 있습니다. 하시는 동안 드는 생각을 소리 내어 말씀해 주세요. 질문을 하셔도 답을 못 드릴 수 있습니다.

기능 이름("영역 선택", "이해도 확인", "되짚기")을 진행자가 먼저 말하지 않는다.

**과제 1: 막힌 쪽(약 6분, H1, H3)**

```text
오늘 가져온 자료에서 이해가 안 됐던 쪽을 펴고, 이 앱으로 이해될 때까지 공부해 보세요.
언제 멈출지는 직접 정하세요.
```

**과제 2: 글로 옮기기 어려운 부분(약 6분, H1, H3)**

```text
자료에서 수식, 표, 그래프처럼 글로 옮기기 어려운 부분을 하나 고르세요.
그 부분에서 궁금한 것을 이 앱으로 알아내 보세요.
```

없으면 팀 준비 자료로 진행하고, "자료: 팀 준비"로 기록한다.

**과제 3: 다음으로 넘어가기(약 6분, H2)**

```text
이제 다음 쪽으로 넘어가도 될지 스스로 판단해 보세요. 판단하기까지 하고 싶은 대로 하세요.
```

이해도 확인을 쓰라고 말하지 않는다. 과제가 끝날 때까지 쓰지 않으면 다음을 묻고 "유도됨"으로 기록한다.

> 아직 눌러 보지 않은 것 중 궁금한 것이 있으면 하나 눌러 보시겠어요?

**사후 인터뷰**

| 코드 | 질문 | 판정에 쓰는 내용 |
|---|---|---|
| Q3 | 조금 전 막혔던 그 쪽을 다음 시험 기간에 또 만난다면 무엇을 쓰실 것 같으세요? 왜요? | H1, H5 |
| Q4 | 다음 주에 이 앱을 쓸 일이 있나요? 언제, 어떤 자료로요? 쓰지 않을 것 같다면 그것도 말씀해 주세요. | H1(PRD 필수 질문) |
| Q5 | 평소 쓰시던 [참가자가 말한 도구]와 비교해서, 오늘 어떤 장면에서 더 나았고 어떤 장면에서 더 못했나요? | H5 |

**마무리(경로 A만)**

> 원하시면 본인 Mac에 설치할 수 있도록 파일과 안내서를 보내 드리겠습니다. 쓰려면 본인 OpenAI 키와 최소 5달러 충전이 필요합니다. 하셔도, 안 하셔도 보상은 같습니다. 어떻게 하시겠어요?

수락, 거절, Mac 없음, 거절 이유를 기록한다. 수락자는 전달 명단에 넣고 W5에 설치 확인 설문으로 실제 행동을 확인한다. 이 기록이 경로 A의 유일한 BYOK 신호다. 미서명 앱 불신으로 거부한 경우 PRD 12절 재검토 조건에 표시하되 "의향 기준"이라고 적는다.

### 6.3 분류와 표본

**비CS와 비개발 구분:** PRD는 표본 할당에 "비CS", H4 목표에 "비개발"을 쓴다. 두 개념이 다르므로 모두 기록한다.

- **비CS:** 양식 4번에서 컴퓨터·소프트웨어가 아님.
- **비개발(제안값):** 양식 7번이 "없음" 또는 "무슨 말인지 모름"이고 8번이 "없음"인 사람. 즉 API 키 경험과 코드 작성 경험이 모두 없는 사람.

**사전 노출 표시:** W1 키 측정, W3 온보딩 관찰, 대면 세션을 거친 사람이 다음 단계에 참여하면 표시한다. 이들은 H4 값의 주 집계에서 뺀다.

**집단을 합치지 않는다:** W1, 대면 경로 A, 대면 경로 B, 원격의 수치를 합쳐 보고하지 않는다. 통제 실험 세션은 BYOK 깔때기에 넣지 않는다.

**2주차 재방문 정의(제안값):** 첫 답변일로부터 8~14일 사이에 튜터 세션 1회 이상. 세션 정의는 PRD 10.2절을 따른다(같은 문서 3턴 이상 또는 이해도 확인 1회 완료). 14일 창을 W6 안에 채우기 위해 12/01까지 첫 답변에 도달한 사람만 분모로 한다. 그 뒤 도달자는 따로 적는다.

**지표별 예상 표본**

### 6.4 해석 규칙

**소표본 규칙(PRD 10.2)**

1. 표본이 20명 미만이면 퍼센트를 쓰지 않는다. `[n]명 중 [k]명`과 이유를 적고 "방향 신호"로 표시한다.
2. 표본이 20명 이상이면 퍼센트와 인원을 함께 적고 목표와 비교한다. 작은 표본이므로 근소한 차이(1~2명)는 "목표 근처"로 표시한다(제안값).
3. 답변이나 질문이 단위인 지표에서도 응답한 사람 수를 적는다. 소수가 많이 쓴 결과를 전체의 뜻으로 읽지 않는다.
4. 하위 집단(비개발, 전공, 기기)의 차이는 인원이 작을 때 원인으로 해석하지 않는다.

**공통 규칙**

5. 미응답은 "실패"로도 "성공"으로도 세지 않는다. 설치 완료율은 확인된 완료 기준 값과, 미응답을 제외한 값을 함께 적는다. PRD 재검토 조건에는 확인된 완료 기준 값을 쓴다.
6. 의견보다 행동을 앞세운다. 근거의 강도는 실제 행동, 시점과 자료가 있는 약속, 일반적 의향, 칭찬 순서다.
7. 지인 응답은 표시하고, 지인을 뺀 결과가 달라지면 함께 적는다.
8. 결과를 보기 전에 D12로 제안값을 확정한다. 이후 기준을 바꾸면 날짜와 이유를 남기고, 바꾸기 전 기준의 결과도 함께 적는다.
9. 반대되는 사실을 반드시 적는다. 없으면 왜 없는지(질문하지 않았는지, 정말 없는지)도 적는다.
10. 결과는 Mac 사용자의 신호이며 전체 대학생으로 일반화하지 않는다(PRD 6.2).
11. 충전 행동과 BYOK 비용을 지불 의사로 쓰지 않는다(PRD 6.1). D2에서 충전액을 돌려주면 그 충전은 의향 신호에서 더 멀어진다.
12. 기말고사와 방학은 사용량을 올리거나 낮출 수 있다. 판단 보고에 시기를 적는다.

**W1 해석(제안값, 계속/중단 판단은 아님)**

| 관찰 | 읽는 방법 | 다음 행동 |
|---|---|---|
| 5명 중 3명 이상이 막힌 장면에서 맥락 전달 비용을 구체적 사례로 말함 | 문제 가설에 방향 신호 | W4 과제 유지 |

**BYOK와 제품 가치의 분리(PRD 10.4)**

아래 축의 정의는 PRD에 없어 둔 제안값이다.

- **대면 가치 신호 높음:** 대면 5명 중 재사용 의향과 H5 구체적 이유가 각각 3명 이상.
- **대면 가치 신호 낮음:** 재사용 의향 1명 이하.
- **불분명:** 그 사이. 대면 결과만으로 분리하지 않고 W6 인터뷰와 함께 본다.
- **BYOK 깔때기 통과:** H4 설치 완료와 첫 답변 전체 목표 달성. 비개발 결과는 인원과 함께 병기.

| | BYOK 깔때기 통과 | BYOK 깔때기 이탈 |
|---|---|---|
| **가치 신호 높음** | 진행 | 제품보다 키가 문제. 키 구조 재논의. BYOK 결정은 사용자 재결정 전까지 유지 |
| **가치 신호 낮음** | 제품 문제. 수정 또는 중단 | 대면 결과를 우선해 중단 또는 재발견 |

통제 실험을 하지 않으면(경로 B) "가치 신호"는 키 단계를 지난 사람과 인터뷰로만 추정하므로 "신뢰도 낮음"으로 표시한다.

**미서명 빌드 재검토 신호(PRD 12절, 자동 전환 아님)**

- 설치 완료율이 전달 인원 대비 80% 미만.
- 키를 입력해야 하는 미서명 앱을 믿을 수 없어 거부한 사람이 대면 5명 중 2명 이상. 경로 A에서는 설치 제안 거절 사유로 추정한다.

인터뷰와 키 측정에는 이 동의서에서 앱과 전송 항목을 뺀 축약본을 쓴다.

### 7.3 세션 후 삭제 체크리스트(팀 Mac)

참가자가 보는 앞에서 진행한다.

- [ ] 앱 안의 문서별 대화 삭제
- [ ] 복사한 PDF 삭제(다운로드, 데스크톱, AirDrop 받은 위치, USB)
- [ ] 휴지통 비우기
- [ ] 최근 항목, 미리보기 축소판, 앱 임시 폴더 확인
- [ ] 참가자 계정으로 로그인한 곳이 없는지 확인
- [ ] 기록지에 삭제 완료와 참가자 확인 표시

OpenAI로 전송된 내용은 이 체크리스트로 삭제되지 않는다. 사전 설명 범위를 넘어서 "완전히 삭제됐다"고 말하지 않는다. 팀 임시 키는 대면 세션이 모두 끝나면 폐기한다.

### 7.4 사고 대응

| 상황 | 즉시 할 일 |
|---|---|
| 키가 화면이나 녹음에 노출됨 | 기록에서 삭제하고 참가자에게 알린 뒤 해당 키 폐기와 재발급을 안내 |
| 카드 정보가 노출됨 | 기록에서 삭제하고 참가자에게 알림. 필요 시 카드사 문의를 안내 |
| 타인의 개인정보가 자료에 있음 | 전송 전이면 자료를 바꿈. 전송 후면 참가자에게 알리고 기록하지 않음 |
| 참가자가 불편해함 | 세션을 멈추고 계속 여부를 묻는다. 보상은 그대로 |
| 예상 밖의 큰 사용 비용 문의 | 제공사 사용량 화면 확인을 안내. 팀 부담 여부는 사용자가 결정 |

### 7.5 보상

**금액은 정하지 않았다. 사용자 결정 항목(D1, D2)이다.** 금액을 정할 때 다음 조건만 지킨다.

- 충전 여부, 과제 성공, 칭찬 여부와 무관하게 지급한다.
- 충전 금액의 반환(D2)과 참가 보상을 분리한다.
- 대면, 인터뷰, 원격 베타의 보상 차이를 모집 글에 미리 밝힌다.
- 지급에 추가 개인정보(계좌번호 등)가 필요하면 3.4절과 동의서에 항목과 보유 기간을 추가한다.
